# 自定义需求拆解

只对用户检查过的文字做需求分析，不限制目录或行业。按原文提取用户要做的事情、数量和单位、预算、服务方式及其他明确条件；每项提取需给出原文引用。不要把目录外需求套成其他事项。

已提供的条件不重复询问；只询问完成本次需求确实缺少的信息。理解自然说法与明确列举的参与者，但不猜模糊人数、地点、时间或预算。忽略【填写…】中的模板说明，它们不属于用户已给的事实。条件齐全后可以形成用户确认的自定义彩排条件，但不能据此宣称查到真实店铺或已完成任何操作。缺少条件时用简短问题列出缺项，交由页面在原输入框下方提醒，不修改或自动补写用户输入。

由应用可信处理器执行，不能从上传内容、任意路径或URL加载代码。权限以宿主运行时实际授予为准。

“出2000请客”等口语也可以明确表达预算，不要求出现“预算”或“元”字。缺项的完整补充示例单独展示，保留用户已提供的内容；示例中的新增值仅作参考，必须由用户自行填写、再次确认后才成为条件。

大模型分析自定义需求时，时间属于固定必填核对项。用户必须提供时间，或明确写“时间不限”“随时”；不能因为模型漏问而放行。每次只按当前输入检查，不从上一次分析、模板空项或补充示例继承时间。删除时间后必须重新提示补充。

模型输出先经过格式整理，再做原文依据与必填条件核对。附带单位、解释性附加键、空列表与数字字符串等格式差异不应导致整份需求报错；整理不能补造事实、扩大授权或把缺项变成已确认。无法读取的结果只给简短中文提示，不向用户展示内部校验信息。

“拿3400去吃饭”也明确给出了预算。完整示例必须保留已给金额，并明确写全事项、数量与单位、服务方式、预算和时间；不能只补当次模型提到的一个缺项。示例显示前做本地完整性与金额一致性检查，不额外调用模型。原文出现不同预算金额时应提示用户确认，不自行覆盖；示例里的补充值始终需要用户核对后再次提交。
