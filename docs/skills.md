# 应用内可信 Agent Skills 运行时（v0.5）

五项技能与应用一起发布在 `trialtrust/skills/`。每项包含 `manifest.json` 和 `SKILL.md`：清单声明ID、版本、最小权限、可选权限和JSON Schema；说明定义执行目标与约束。它们属于本应用的受控技能包，不是外部市场自动安装器，也不是全局Codex技能。

## 实际执行链

```mermaid
flowchart LR
    D[白名单发现 元数据和摘要] --> L[匹配任务 按需加载说明]
    L --> G[校验输入与能力授权]
    G --> H[应用可信处理器]
    H --> V[校验输出 Schema]
    V --> E[版本 权限 输入输出摘要 事件]
    E --> C[报告与检查点]
```

`discover()`返回元数据及完整性摘要，不把全部说明塞进上下文；`load()`对清单与正文计算摘要，匹配的说明才加入当前模型上下文或传给处理器。`invoke()`要求最小能力存在，且调用请求属于技能声明和宿主授予的交集，再验证输入、调用宿主处理器并验证输出。加载器拒绝任意路径、URL和未列入白名单的名称，不动态导入用户脚本。

## 每项技能做了什么

| 技能 | 路由与所在模块 | 输入 → 输出 | 实际权限 | 可观察效果 |
|---|---|---|---|---|
| `mandate-review` 委托边界核对 | 第一次执行工具前 / 条件与工具模块 | 4项委托 → 版本摘要、允许动作 | `read_conditions` | 条件摘要一致；快照恢复不会重复记首次核对 |
| `evidence-retrieval` 现行证据检索 | `search_rules` / 证据模块 | 查询、领域 → 检索模式与命中证据 | `read_fixture` | 真实执行范围/现行过滤、BM25及可选向量/RRF |
| `plan-verification` 费用与授权核验 | `check_plan`、`submit_draft` / 草稿模块 | 金额、证据、数量、方式 → valid及原因 | `check_constraints` | 错金额、缺证据、未见过的ID不能通过 |
| `pair-audit` 对照事实审阅 | 两次执行完成后 / 对照模块 | 原始与变化观测 → 已核对/已剔除事实 | `read_reports`；真实审阅另需`model_call` | 模型可以挑重点，代码按值和类型剔除不实事实 |
| `request-analysis` 自定义需求拆解 | 替身检查同意后 / 手动需求模块 | 已检查文本 → 明确字段、澄清、证据需求、能否彩排 | `analyze_text`；选真实模型另需`model_call` | 未知需求不映射到默认场景，额外要求保留可见 |

前三项技能说明进入执行器系统消息，模型通过工具选择触发宿主路由；不是让模型获得自行修改白名单的权力。向量调用属于宿主已确认的检索配置，沿用现有Embedding预算，技能本身不能修改模型、网络地址或额度。

对照审阅和需求拆解的可选模型调用都在对应技能处理器内，使用现有共享账本、固定Provider与保守预算；未授予`model_call`时不能执行真实模型分支。离线模式仍运行确定性处理器，但不会把它记作模型调用。

## 怎样证明不是只放了文档

结果区的“本次实际技能调用”来自报告的 `skill_events`；JSON中包括技能ID、版本、清单+正文摘要、实际能力、状态、耗时和输入/输出SHA-256。技能事件不是检索成功率或性能提升证明；当前没有“Skills比不使用Skills更快/更准确”的消融结论。这里可证明的是路由真的执行、权限受控、产物可检查。

70项新增后端回归覆盖12领域×5条件，及未知技能/路径、缺能力、错误Schema、模型不能扩展领域、指令实际加载和快照事件恢复。旧记录没有技能事件时，页面明确说明是旧版，不补造调用。模型及云端实测另保存在版本化原始记录中。

## 与 MCP、普通提示词的区别

本应用还保留两个真实只读stdio MCP工具，用于外部客户端检索规则和检查方案；网页直接调用同源后端，不通过外部MCP连接。MCP定义工具接入面，Skills定义受控任务说明与执行契约。这里只有提示词时不算完成运行时；目前的实现还包含清单发现、路由、Schema、能力检查、宿主执行、事件和恢复。

此实现信任随应用发布的维护者代码，尚无不可信技能代码的进程沙箱、第三方签名分发、跨进程权限管理或插件市场。不能把白名单能力检查称为任意代码的安全执行保证。
