# 从场景定义到公开运行：七个工程阶段

本文按实现依赖记录项目的开发过程和复现路径。七个阶段是工程组织方式，不表示每一步都对应独立历史提交；当前GitHub仓库从v0.4公开快照开始记录后续变更。

## 阶段一：确定问题与可验证边界

产出：明确一次生活委托需要观察的行为，以及产品假设；查阅相近工作，保留差异和限制。

选择陶艺和分体挂机清洗作为有限合成领域，把数量、履约方式、预算、费用和退改依据表达清楚。暂不连接真实预约和支付，便于独立确定期望结果。见[产品设计](product.md)。

复现检查：用4人陶艺、自取、300元预算手算280元；用2台清洗、上门、220元预算手算210元。若不能先确定真值，就不把模型回答当作核验依据。

## 阶段二：实现数据、委托与工具环境

产出：版本化资料、不可变委托、查询/检查/草稿工具、独立核验器。

`mandate.py`固定确认过的字段及授权摘要；`scenarios.py`构造现行、旧版和跨范围资料；`sandbox.py`验证金额、数量、附加费、证据及授权。世界快照保存实际观察过的资料，避免拿未查询过的证据生成草稿。

复现检查：错误价格、缺退改、跨领域或旧版资料不能通过核验；越权尝试被计数，真实世界操作仍为0。

## 阶段三：接入单Agent工具循环

产出：真实模型的Function Calling循环，工具结果反馈、参数验证、轮次上限和终止分类。

先用离线行为验证接口和状态，再显式启用百炼真实模型。`workflow.py`控制消息循环，`provider.py`提供模型和Embedding调用；输出截断或部分工具参数不会被当作完整动作执行。

复现检查：默认离线CLI可运行；真实模式能自主检索并起草，但仍受同一套工具规则约束。

## 阶段四：建立检索链与消融

产出：原始BM25、规则分面BM25、真实稠密、混合RRF四条可比较路径，以及冻结开发集与逐问结果。

先过滤领域和时效，再生成向量。缓存绑定内容/版本，检查维度与有限数值。检索结果必须保留ID和来源，便于后续核验。

复现检查：`python -m trialtrust.evaluate`无需模型；`--dense`显式调用Embedding并消耗额度。保留两条无答案问题仍返回资料的失败事实，不只展示成功指标。见[评测记录](evaluation.md)。

## 阶段五：加入对照、多角色和检查点恢复

产出：设计者、两次隔离执行、只读审阅者、事实核对与父子图检查点。

设计者只能改变一个受支持测试条件。两个执行固定同一委托，状态隔离。审阅者输出结构化事实而不是自由安全结论；代码逐条核对。父图在子图提交后崩溃时，通过子图检查点复用产物，避免盲目重复模型请求。

复现检查：运行`tests/test_suite.py`，验证非法设计、错误审阅事实及恢复路径；成组记录的委托哈希应一致。

## 阶段六：连接网页、匿名会话与MCP接入面

产出：条件确认、替身预览、未建模内容、运行状态、对照卡片、工具回放、审阅、导出和历史。

网页原文的格式替换留在浏览器，用户明确确认后才发送替身提取；试运行只使用结构化条件。会话校验保证记录归属，写操作检查同源，后台任务可显式恢复。独立MCP服务提供两个只读工具，协议测试通过子进程实际验证。

复现检查：两个匿名会话不能互读记录；审阅可重复相同决定，冲突决定失败；离线流程可在没有模型密钥的环境运行。见[复现指南](reproducibility.md)。

## 阶段七：部署、验证与公开材料

产出：Docker核心入口、魔搭Gradio入口、公开体验、原始验收记录、封面与说明。

源代码通过Git直接推送到魔搭仓库，再调用平台部署。托管适配解决了根Gradio配置、静态资源路由冲突、动态内部Host、跨站iframe Cookie和JSON下载通道等问题。每次以应用实际检查结果判断是否可用，而不只看平台Running。

2026年10月16日已完成无账号云端API的离线对照与一次真实模型/Embedding检查。本地托管网页交互与下载已验证；v0.5公开门户桌面/手机、对照、确认和审阅已完成自动化交互验收。云端原生下载回执尚未捕获，提供只读JSON查看/复制备用入口。真实用户研究仍待完成。

## 下一轮验证计划

| 优先级 | 工作 | 需要回答的问题 |
|---|---|---|
| P0 | 人工检查公开页面、组织真实试用 | 用户能否理解条件遗漏、对照结果和授权边界？ |
| P1 | 独立人工审阅开发样本并补充保留集 | 现有核验和检索效果能否在未参与设计的样本上成立？ |
| P1 | 固定变化设计与设计Agent对照 | 新增角色是否改善故障覆盖，增加多少成本？ |
| P1 | 无答案校准与失败提示 | 什么情况下应明确说证据不足？ |
| P2 | 在单一领域扩展现实可核验资料 | 来源更新、授权与现行价格如何维护？ |
| P2 | 第三方执行器接口和多进程协调 | 状态、费用与权限如何跨进程保持一致？ |

计划项不是已交付能力；每项完成后记录版本、验证方法、原始结果和仍存在的反例。

## v0.5 迭代：可理解的操作与可执行技能

在原七阶段之上完成四步新手引导、桌面/手机布局、可见原生勾选样式和独立确认状态。历史只渲染报告，不回填表单或授权；任何新条件须重新确认。

场景通过同一后端目录扩为四类十二项，每项有独立合成资料及金额真值。新增60项场景矩阵回归，另验证未知文字、模型梳理不能扩展执行范围、技能权限与恢复。自定义需求有规则和显式真实模型两条路径；都不编造现实资料。

五项应用内技能经可信运行时路由、校验和记账。技术取舍与证据见[Skills说明](skills.md)。公开源代码仓库记录工程过程；真实用户试用仍需进一步开展。
